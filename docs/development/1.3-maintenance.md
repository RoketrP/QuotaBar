# 1.3.0 maintenance notes (unreleased)

## Scope

1. Recover from helper exit, startup failure and unresponsive requests. Requests have a 20-second deadline and cancellation; failure recreates the connection. Retries back off through 5/10/20/40/60 seconds, or 5 minutes for a reported 429. Polling starts before the first connection attempt. Wake notifications request an immediate refresh.
2. Choose the main, 5-hour, weekly or lowest-remaining Codex window. Menu bar labels identify the actual window. Missing explicit selections show `--%`. Failure or 180 seconds without success marks existing data stale in the menu bar, details and HUD.
3. Opt-in local snapshot history with 30-day retention, 7/30-day charts, CSV export and explicit clear. Samples are limited to one per minute per bucket/window. Charts split at resets and gaps over 5 minutes, and reduce drawing work while retaining local extrema. CSV retains every sample.

## Privacy and account boundaries

- Default: no persistent quota history. Samples contain timestamps, bucket IDs, window lengths, remaining percentages and reset times, never credentials, emails or conversation content.
- A local SHA-256 account fingerprint prevents reuse across different accounts after restart; it is excluded from history and export. Logout/account changes clear history.
- Demo snapshots are never recorded. The debug-only `--demo --demo-history` preview uses synthetic history in memory; it does not persist synthetic samples.
- Writes are atomic, with private file permissions. Corrupt files are preserved until explicit clear. Read/write/export errors are visible.
- Late responses from an obsolete operation or account revision cannot replace current data. Refresh requests are coalesced; obsolete helper callbacks are ignored.

## Design reference

Reviewed [majiayu000/quotabar](https://github.com/majiayu000/quotabar/tree/03c33b46655ff0c3c5c9bc2b3414c50430e9b5fc), especially its most-constrained-window semantics, explicit stale readings, retry/backoff boundaries and separation of quota from cost estimates. This change uses an independent native Swift implementation and adds no dependency on that project. Multi-provider and cost-estimation features remain outside this change.

## Validation

- SwiftPM runs both core and application tests, including fake-helper subprocesses for initialization, timeout, exit, restart and cancellation.
- Model/store tests cover automatic background recovery, wake refresh, refresh coalescing, stale snapshots, late results, account changes, persistence, opt-in, logout and corrupt files.
- Core tests cover selection, missing windows, freshness, retention, sampling, CSV escaping, chart segmentation/reduction and retry delays.
- The Xcode scheme runs the core tests and builds the native app. Application integration tests run through SwiftPM.
- Native UI preview checks use illustrative data and a separate bundle identifier. They verify selector changes, history chart controls and the CSV save dialog.

Real-account sign-in, actual network disconnect/reconnect, physical sleep/wake and Apple notarization remain separate validation gates. No public release is created by this change.
